# AI agents

An **AI controller** makes an entity decide where to go by itself. Give an entity
one and, with no script at all, it can:

- **find its way** around a level: round pillars, through doorways, up stairs
  and ramps
- **hunt** the player or other entities it can see, and close to attack range
- **work objectives**: walk to a volume, stay there for a while, and report the
  job done — or patrol a list of them forever
- **walk a waypoint path** you lay out in the level, doing what each point says:
  wait, run, hold its fire, or take cover

A controller only ever sets the entity's velocity and turns it to face the way it
walks. Everything after that — gravity, walls, being shoved by a crate, climbing
a step — is the same collision every other entity gets. That is why an agent is
stopped by a door it did not know was shut, with no AI code involved.

`resources/entities/guard.yaml` is the worked example: a sentry that patrols the
volumes tagged `patrol`, hunts the player on sight, and stops at arm's length.
Its script, `scripts/guard.flang`, only reacts to what the controller reports.

## Giving an entity a controller

Select a placed entity and open its **AI** group, or open a type in the entity
editor and use the **AI** group there. **Give it an AI controller** adds one with
defaults that walk.

An agent's *size* comes from its **bounds**: the radius is the larger of the X and
Z half-extents, and the height is twice the Y half-extent. Paths are planned so
that a body that size fits — a doorway narrower than the agent, or a ceiling
lower than it, is not on its route. Give an agent real bounds.

An agent also wants **Collide with world** and **Gravity** on, so that it walks
on floors and is stopped by walls. The panel says so when they are off. An agent
with no gravity follows the heights of its route by itself, the way a hovering
drone would.

### Movement

| Field | |
| --- | --- |
| **Speed** | walking speed, in units per second |
| **Acceleration** | how quickly it reaches that speed and stops again |
| **Turn rate** | how fast it turns to face the way it walks, in degrees per second; 0 turns at once |
| **Step height** | the tallest step it climbs; 0 uses the level's player step height |
| **Arrive radius** | how close to a destination counts as there |
| **Face the way it walks** | turn the entity to its direction of travel. Off leaves facing to a script or an animation |

An agent faces its local **−Z**: a yaw of zero looks toward −Z, the same axis a
vehicle drives along. Build a model to face that way, or rotate its attachment.

### Targets

**Targets** is what the agent hunts. Each entry is one of:

- `player`
- an entity ID, such as `intruder_3`
- `#tag`, which is every entity carrying that tag

The **Add...** list offers what the open level has.

An agent **notices** a target in either of two ways:

- **It hears it.** The target is closer than **Hearing range**, whichever way the
  agent faces and whatever is in between.
- **It sees it.** The target is within **Sight range**, inside **Field of view**
  (degrees across the whole cone, so 360 is all the way round) and, when
  **Needs a clear line of sight** is on, nothing in the level's geometry is in the way.

Looking costs a ray cast, so an agent looks about five times a second rather than
every frame.

Once it has a target, the agent keeps it while it can still notice it, even if
something else on its list comes nearer. When the target goes out of sight, the
agent goes to where it last saw it. After **Lose after** seconds with no sight of
it, the agent gives up.

**On target** decides what it does about one:

| | |
| --- | --- |
| `chase` | walk to it, stop at **Attack range**, and post `:target_in_range:` — repeated every **Attack interval** while it stays that close |
| `watch` | stay put and turn to face it: a turret, a sentry on a wall. It still posts `:target_in_range:` |
| `ignore` | only tell the script: `:target_acquired:` and `:target_lost:` still arrive |

The controller never attacks. `:target_in_range:` is where your script does:

```flang
def swing(:target_in_range:, src ref, target ref) -> null
    target <- (:damage:, @self, 10)
end
```

### Objectives

**Objectives** lists the volumes the agent works through, each as a volume ID or
`#tag`. Only volumes marked as objectives count (see below).

| Field | |
| --- | --- |
| **Order** | `sequence` takes them in list order; `nearest` takes the closest not yet done; `random` takes any not yet done |
| **Loop** | start the list again once every objective on it is done. A patrol is a looped sequence |

A `#tag` entry expands to the tagged volumes in the order the level lists them.

To take an objective, the agent picks a spot inside the volume that it can
actually reach — at random, so three guards sent to one room spread out rather
than queueing for its centre. It walks there, **performs** the objective for the
volume's **Duration**, and then takes the next one. An objective it cannot reach
is skipped and reported with `:ai_path_failed:`, so one badly placed volume does
not freeze a whole patrol.

A target interrupts an objective. When the agent loses the target, it goes back
to the same objective and starts performing it again from the beginning.

Tags matter for **types**. A type does not know which level it will be placed in,
so give a type its objectives as `#tags` and tag the volumes in each level. A
placed entity may still name its own volumes by ID.

### Waypoint path

**Waypoints** names a waypoint animation for the agent to walk, stop by stop.
Each point's **AI** group says what to do there; see
[Waypoint paths](#waypoint-paths) below. A path is walked ahead of the
agent's objectives. The objectives take over once a path that does not loop is
finished. **Loop the path** walks it again from the first point after the last.

A type can name a path it carries itself, by the name the type gives it.

### Idle

With nothing to do, an agent stands still. Set **Wander radius** and instead it
strolls to random reachable spots within that distance of where it started,
waiting roughly **Wander pause** seconds between strolls.

**Idle animation** and **Move animation** are played on the entity's attachments
as it stops and starts, when it has animations by those names. An objective's
own **Animation** plays while the agent performs it.

## Objective volumes

Any volume can be an objective. Open its **AI Objective** group and tick **Agents
are sent here to act**.

| Field | |
| --- | --- |
| **Enabled** | switch the objective off while keeping its settings. The volume's own Enabled switches it off too |
| **Action** | the atom posted when the objective is done: `hack` posts `:hack:`. Leave it empty for `:objective_complete:` alone |
| **Duration** | how long, in seconds, an agent stays inside to perform it. 0 is done on arrival |
| **Animation** | played on the agent while it performs, if it has an animation by that name |
| **Capacity** | how many agents may work it at once, counting agents on their way to it. 0 is no limit. An agent whose next objective is full waits its turn |
| **Only agents tagged** | only agents carrying this tag take it: a door only engineers repair |
| **Face the volume's front** | turn a performing agent to face the way the volume faces (its −Z), so a console is worked from in front |
| **Only once** | switch the objective off after it is first done |

The group lists which agents in the level name this volume. When none do, it says
so.

When an agent finishes an objective, **both** the agent and the volume receive
the objective's action atom and then `:objective_complete:`. So the volume's
script is where "the console has been hacked" lives, and the agent's script is
where "I hacked a console" lives:

```flang
-- on the console volume
def hacked(:hack:, src ref, console ref) -> null
    @vault_door.prop.enabled = false
    log(format("{} opened the vault", src.id))
end
```

An objective is still an ordinary volume. It still fires `:enter:` and `:exit:`,
and it can still hold fog.

## Waypoint paths

A waypoint animation is a path of arrows you lay out in the 3D view: **Add >
Waypoint Animation** places the first point, and **Ctrl+click** adds the next
(see [Waypoint animations](02-building-levels.md#waypoint-animations)). A door
or a lift sent along one glides through its points on a timeline. An **AI
agent** walks it instead:
- It finds its own way to each point on the level's navigation, at its own
  speed, and ignores the points' times.
- It does what each point's **AI** group says when it gets there.

Give an agent a path in its AI group's **Waypoints** row, or send it along one
from a script with `ai_follow_waypoints`.

### What a point can say

Select a point and open its **Point N AI** group. Tick **AI agents stop and act
here** to give it instructions. A point without them is a corner the agent passes.

A point's settings govern the **leg arriving at it** and **the stop itself**.
"Run to that crate and take cover behind it" is one point.

| Field | |
| --- | --- |
| **Stop** | **(the point itself)**, or a **volume**: the agent then goes anywhere inside it that it can reach, and takes cover anywhere inside it. **Create Volume Here** places a volume over the point and links it |
| **Wait** | how long, in seconds, the agent stays after it arrives. 0 passes straight through |
| **Wait for script** | hold here, after the wait, until a script calls `ai_continue(@agent)` |
| **Speed ×** | multiplies the agent's speed on the way here: 2 runs, 0.5 creeps |
| **Targets** | how it treats a target on the way here and while it stops (below) |
| **Take cover** | on arrival, move to the nearest reachable spot hidden from danger (below) |
| **Cover radius** | how far from the point cover is looked for; a volume stop searches the volume instead |
| **Face the arrow while waiting** | turn the way the arrow points |
| **Animation** | played on the agent while it waits here |

**Targets** has four settings:

| | |
| --- | --- |
| `inherit` | the agent's own **On target** — except at a point that takes cover, which holds |
| `chase` | leave the path to chase, and walk back to the point after |
| `hold` | keep to the path. It turns to face a target it can see and posts `:target_in_range:` when one is close enough, so it fires on the move |
| `ignore` | keep to the path; the script is told about targets and nothing more. A stealthy leg |

### Taking cover

At a point that takes cover, the agent looks for spots it can reach near the
point, or inside its volume. A spot counts as cover when nothing in the level's
geometry lies between the danger's eye and both the agent's chest and its head.
Of those spots, it takes the one nearest to itself, and then nearest to the
point.

The **danger** is the agent's target when it has one. With no target, it is
whatever lies the way the point's **arrow faces**. You can therefore say "behind
this wall, facing the door" before anyone has come through the door.

Twice a second the agent checks that its spot still hides it. When a target has
walked round the cover, the agent posts `:cover_lost:` and looks for more. On
reaching a spot it posts `:cover_taken:`.

A cover point holds the agent there for its **Wait**, and for as long after as
the agent still has a target. Hiding until the danger is gone is what taking
cover is for.

In the 3D view, a cover point draws a blue ring for its cover radius, a point
the agent waits at draws a small square at its foot, and a volume stop draws a
line to its volume.

### What the script hears

Arriving at each point posts the same `:waypoint:` (and the point's own
**Events**) that a brush sent along the path gets. Walking off the end posts
`:waypoints_end:`. Scripts written for one therefore work for the other:

```flang
def at_point(:waypoint:, src ref, path ref, index int) -> null
    if index == 2
        @alarm.prop.enabled = true
    end
end
```

When an agent chases a target away from a point it had already reached, and then
comes back, it arrives again and hears `:waypoint:` again.

## Seeing what an agent can do

Tick **Show navigation** in an agent's AI group, or in a volume's AI Objective
group. The 3D view draws the edges of the walkable area around the camera, for a
body the size of the selected agent (or a player-sized one when no agent is
selected). With an agent selected, it also draws in orange the route that agent
would walk through its waypoint path, or through its objectives when it has no path. A leg drawn in red cannot be walked.

The walkable area comes from the level's own brushes. Nobody marks floors as
walkable: any surface flatter than 45°, with room above it for the body, is a
place to stand, and a neighbouring surface within a step of it can be walked to.
The walkable area is kept a body's radius back from walls and ledges.

It is rebuilt automatically whenever the level's shape changes: an edited brush,
a moved chunk, or a chunk a script switches off. Three kinds of geometry are
deliberately left out:

- **Dynamic brushes.** A door moves, and a door recorded as shut would be a wall
  forever. Collision still stops an agent at a shut door, and the agent plans a
  new route when it makes no headway.
- **Vehicle interiors and entities' own brushes.** Their coordinates move with
  their owner. An agent aboard a vehicle notices and reacts, but does not walk.
- **Disabled chunks.** They are not there.

## Scripting an agent

A script overrules the controller with verbs, reads what it is doing, and tunes
it while it runs. The full reference is in `SCRIPTING.md`.

```flang
ai_move_to(@guard, @alarm_panel)    -- go there; beats target and objectives
ai_stop(@guard)                     -- cancel that
ai_target(@guard, @player)          -- hunt this, and never give up on it
ai_target(@guard, null)             -- back to hunting what it sees
ai_objective(@guard, @console)      -- do this one now
ai_follow_waypoints(@guard, @beat)  -- walk this path, doing what its points say
ai_continue(@guard)                 -- send it on from the point it is waiting at
path = find_path(@guard, @exit)     -- the corners of a walkable route, or null
if can_see(@guard, @player) ...     -- nothing solid in between?
```

| Event | Arguments | When |
| --- | --- | --- |
| `:target_acquired:` | `src ref, target ref` | it noticed something on its list |
| `:target_lost:` | `src ref, target ref` | it gave up after Lose after, or the target was destroyed |
| `:target_in_range:` | `src ref, target ref` | the target is in sight within Attack range; repeats every Attack interval |
| `:ai_arrived:` | `src ref` | it reached where `ai_move_to` sent it |
| `:ai_path_failed:` | `src ref` | it could not find, or could not follow, a way there |
| `:objective_reached:` | `src ref, objective ref` | it arrived and began performing — sent to the volume too |
| *the Action atom*, `:objective_complete:` | `src ref, objective ref` | it finished — sent to the volume too |
| `:objectives_done:` | `src ref` | it finished a list that does not loop |
| `:waypoint:`, and a point's own events | `src ref, path ref, index int` | it reached a point of the path it walks |
| `:waypoints_end:` | `src ref, path ref` | it walked off the end of that path |
| `:cover_taken:` / `:cover_lost:` | `src ref` | it reached a hiding spot at a cover point / the spot stopped hiding it |

`src` is always the agent.

Properties: `ai_enabled`, `ai_state`, `ai_target`, `ai_objective`,
`ai_destination`, `ai_on_target`, `ai_targets`, `ai_objectives`, `ai_waypoints`,
`ai_waypoint_index`, `ai_in_cover`, `ai_waiting`, and the tuning
numbers `ai_speed`, `ai_accel`, `ai_turn_rate`, `ai_sight_range`, `ai_fov`,
`ai_hearing_range`, `ai_lose_time`, `ai_attack_range`, `ai_attack_interval` and
`ai_wander_radius`. An objective volume has `objective_enabled`,
`objective_action`, `objective_duration` and `objective_agents`.

A guard that runs once it is alerted:

```flang
param alert_speed float = 5.5

def remember(:spawn:) -> null
    @self.state["walk"] = @self.prop.ai_speed
end

def alerted(:target_acquired:, src ref, target ref) -> null
    @self.prop.ai_speed = ?alert_speed
end

def calmed(:target_lost:, src ref, target ref) -> null
    @self.prop.ai_speed = @self.state["walk"]
end
```

## Play and pausing

Controllers run only during play, and they stop while the game is paused. Every
agent starts its round again when play starts and when a level loads: back to
the first objective, with no target and no command. Nothing a controller does in
play is saved to the level.
